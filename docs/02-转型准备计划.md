## 〇、定位：一条路，不是两条路

**路线决策（2026.10 定）：保持前端身份求职，转型在下一份工作里完成。**
求职期以前端拿 offer（确定性来源），offer 筛选加三个条件：①公司/团队有 AI 业务或自研 AI 工具；②业务有复杂度；③有 Node/服务层的全栈空间。入职后 3~12 个月把 AI 工程化做成主职责，下一份简历头衔自然升级为"AI 应用工程师"。12 月作品上线后小批量试投 AI 岗，用市场反馈校准转型节奏——不裸转，用最强的牌（多端小程序资深前端）求职，用岗位内的生产经验转型。

**目标岗位画像：AI 全栈应用工程师（前端 + Node 服务层 + LLM/Agent 编排）**

不做传统全栈（Java/Go 微服务）的理由：从零补、与 6 年前端资历错位、竞争者众。
选 AI 全栈的理由：2026 年 AI 应用岗最想要的正是这个画像，且已有差异化起点——
多 Agent 协作的团队实战 + 技术分享、Claude Code/Codex/ZCode/Trae 深度使用、50% 提效数据。

**投递时匹配的 JD 关键词**：AI 应用工程师、Agent 工程师、LLM 应用、前端全栈（Node 方向）。
**避开的 JD**：要求 Java/Go 微服务深度、K8s 运维深度、算法背景（模型训练/微调）的岗位。

## 二、三阶段任务清单

### 阶段一：Node 服务端补齐（2~4 周，业余时间）

**学：**
- [ ] NestJS 上手（推荐；TS 亲和、模块化结构接近前端工程习惯）
- [ ] MySQL：建表、索引、事务、联查（够用即可，不深钻 DBA 方向）
- [ ] Redis：缓存模式、会话存储
- [ ] 鉴权：JWT 全流程（签发/刷新/黑名单）
- [ ] 面试八股同步补：HTTP 缓存、跨域、XSS/CSRF、进程线程、事件循环

**作品 #1：发布管理系统 v2（后端完整版）**

- [ ] 把简历里"从 0 到 1 搭建的发布管理系统"重写为全栈版：NestJS + MySQL + Redis + JWT
- [ ] 核心功能：项目管理、发布流水线（触发/审批/回滚）、操作日志
- [ ] Docker 部署，README 精修（架构图 + 启动一条命令）
- [ ] 面试话术锚点："我把内部工具重构成了生产级后端服务"——顺手展示设计能力

### 阶段二：Agent 开发核心 + 主作品（3~4 周）

**学（原理 > 框架）：**
- [ ] function calling / tool use：能手写一个最小 agent loop（while + 工具调用 + 结果回填）
- [ ] MCP 协议：写一个自己的 MCP server（哪怕是包一层内部 API）
- [ ] RAG：embedding、向量库（pgvector 起步）、chunking、rerank 概念
- [ ] 评测：给 Agent 写 eval 用例集（怎么衡量"好"——准确率、成本、延迟）
- [ ] 框架：Vercel AI SDK（TS 系，前端最顺）；LangGraph 了解概念即可
- [ ] streaming：SSE 流式输出 + 前端 chat UI 的渲染优化（这是前端主场）

**作品 #2（主项目）：小程序多端兼容 Agent**

- [ ] RAG 知识库：把 uni-app 多端踩坑经验结构化（抖音滚动、provide/inject、安全区、各端 API 差异……）
- [ ] Agent 能力：输入代码 diff/组件，输出多端兼容风险报告（工具调用 + RAG 检索）
- [ ] 加分项：MCP server 形式暴露，能被 Claude Code/ZCode 直接调用
- [ ] 选题价值：贴身业务——面试讲项目时，6 年多端经验和 AI 实现互相印证，没有竞争者能复制这个场景

### 阶段三：材料重组（1~2 周）

- [ ] 简历技能行重排：`Vue3/TS/小程序多端 + Node.js（NestJS、MySQL、Redis）+ LLM 应用（Agent 编排、MCP、RAG）`
- [ ] 两个新作品写进项目经验（各自 2~3 条量化成果）
- [ ] GitHub 主页置顶两个项目，README 配架构图与在线 demo
- [ ] 05-面试题库.md 新增"全栈 / AI Agent"题板块（见下文必考清单）
- [ ] 技术栈行保留 Java（B305 新能源项目已补实证）；React 视目标岗位保留

### 6.3 沐晨 7 天冲刺（主攻）

**Day 1：评测方法论**

- 读 terminal-bench 3.0 与 SWE-bench 的任务设计：任务如何定义、如何判定通过（FAIL_TO_PASS / PASS_TO_PASS）。
- 分清三类指标：功能正确性、过程合规、工程质量。
- 产出：一页笔记，能口述"一个任务怎样才算通过"。

**Day 2：Rubric 五维**

- 按正确性、边界处理、可读性、安全性、可维护性写 1-3 分档描述。
- 要求每条可判定，避免"代码优雅"这类模糊表述。
- 产出：一份可复用的 rubric 模板。

**Day 3-4：自建评测集（核心产出）**

- 从自己项目里挑 20 个真实问题：多端兼容、异步竞态、空值边界、权限绕过、分页异常。
- 每个任务写清：需求、初始代码、验收检查项、rubric。
- 跑 2 个模型（如 Claude 与一个国内模型），记录通过率、失败类型、耗时与成本。
- 产出：仓库（可私有）+ 一页评测报告。这是面试时唯一能"拿得出手"的证据。

**Day 5：Docker 与问题复现**

- 写 Dockerfile / Compose，把项目跑起来并执行测试。
- 练完整链路：拉代码 → 看 diff → 跑测试 → 定位失败原因。
- 产出：一条命令启动的复现环境。

**Day 6：Python 阅读**

- 能读 pytest 用例、看懂失败堆栈、改简单断言。
- 不追求写 Python 服务，只求读懂评测脚本。
- 产出：跑通一个开源项目的 Python 测试。

**Day 7：话术与模拟**

- 准备三个故事：边界诊断（抖音滚动 / provide/inject）、AI 输出审核与修正、规范与可读性。
- 模拟必问题："你没有评测经验，凭什么做这个岗？"
- 产出：STAR 稿 + 反问清单。

验收标准：5 分钟内讲清一个任务的评分设计；能现场展示评测集与报告；能诚实说明经验边界。

验收标准：demo 能启动并演示；每类测试至少一个可运行用例；不宣称"5 年经验"。

> 时间不够时的取舍：只做 Spring Boot 最小服务 + Redis 缓存，其余只准备概念与话术。不要为了这家放弃沐晨的评测集。

### 6.5 三家共用的必答题

1. **你怎么审核 AI 生成的代码？**
   先跑测试与静态检查，再人工看边界、异常处理、安全和可维护性；补一个真实纠错案例，说明你改了什么、为什么。
2. **你怎么定位线上问题？**
   复现 → 缩小范围 → 日志与埋点 → 二分定位 → 修复 + 回归。用德邦多端问题作为案例。
3. **你没有正式评测 / CR 经验（沐晨）或 React/Angular 深度（赛力斯）或 Java 微服务年限（Int-speed），怎么补？**
   承认边界，展示已有实证（沐晨：评测集 + rubric；赛力斯：Vue3 + 鸿蒙 + 规范推动；Int-speed：B305 Java + 可运行 demo），强调可迁移能力。
4. **6 年经验为什么投 1-3 年（沐晨）/ 薪资更低（三家均低于常规区间）的岗位？**
   说明看重的方向：沐晨的 AI 评测、赛力斯的车厂多端、Int-speed 的 Java 补强；接受阶段性薪资；不贬低自己，也不虚构年限。

### 6.6 与原路线的关系

- 赛力斯要求的系统设计 / 性能优化 / 前沿技术，正好是你现有经历的再包装，**不增加新技能学习量**，属于"打磨话术 + 补数字"型冲刺。
- 沐晨要求的评测能力，补上阶段二"评测"缺口，属于长期加分。
- Int-speed 的 Java 补强是备选，2 周为上限；不改变"前端 + Node + AI"主线。
- B305 新能源项目（Java + MySQL + AngularJS，交付并运营）已补实证，保留 Java 技术项。

## 七、Java 学习路径（第二语言，2 周突击 / 6 周长期）

> 定位：Java 不是 AI 全栈主线，只作为第二后端语言与面试材料。投入必须有上限，避免挤占 Node + LLM 主作品的时间。

### 7.1 先定目标

| 目标 | 投入 | 学到什么程度 |
|---|---|---|
| 面 Int-speed 这类 Java 微服务岗 | 2 周突击 | 能写、能讲、能跑 demo |
| 长期作为第二语言使用 | 6 周 | 能独立交付一个服务 |

### 7.2 四阶段路径（按 2 周突击压缩）

**阶段 1：语法恢复（2-3 天）**

- Java 17：集合、泛型、异常、Lambda / Stream、Optional、record。
- 方法：用 TypeScript 类比记忆——`interface` 几乎相同，注解约等于装饰器，依赖注入约等于 provide/inject。
- 不读《Java 编程思想》，直接看官方教程并写代码。

**阶段 2：Spring Boot 3（4-5 天）**

- IoC / DI、REST 接口、参数校验、统一异常、拦截器与过滤器、多环境配置。
- 产出：3 个接口（列表、详情、新增）+ 分页 + 全局异常处理。

**阶段 3：数据层与中间件（4-5 天）**

- MyBatis-Plus：CRUD、分页、条件构造器。
- MySQL：索引、事务、慢查询各练一遍，不深钻 DBA 方向。
- Redis：缓存模式、分布式锁、穿透 / 击穿 / 雪崩。
- Kafka：Topic、消费者组、幂等、积压处理（本地 Docker 起）。

**阶段 4：测试与交付（2 天）**

- JUnit5 + Mockito + Testcontainers 跑通一个模块。
- Docker Compose 一条命令启动，README 写清架构与启动方式。

**Spring Cloud**：Nacos / OpenFeign / Gateway 只花 1 天了解概念与架构图，不搭真实集群；面试能说清"解决什么问题"即可。

### 7.3 必须能回答的面试点

1. 线程池核心参数与拒绝策略
2. JVM 内存区域与常见 GC
3. Spring Bean 生命周期、循环依赖如何解决
4. `@Transactional` 在哪些情况下失效
5. MySQL 索引失效场景、事务隔离级别
6. Redis 缓存与数据库一致性、分布式锁注意点
7. Kafka 如何保证顺序、消费积压如何处理

### 7.4 验收作品

一个服务包含：用户与任务两张表 → JWT 登录 → 列表分页 → Redis 缓存 → Kafka 异步任务 → 单元测试 → Docker Compose 启动。能演示、能讲设计，比刷 200 道八股更有效。

### 7.5 避坑

- 不从 SSM / SSH 老框架学起，直接 Spring Boot 3。
- 不背八股而不写代码，面试官一问场景就会露。
- Java 投入不超过 2 周，除非明确放弃 AI 全栈主线。
- 不宣称"5 年 Java 经验"：B305 项目是 2016-2018，如实说明年限与深度。
